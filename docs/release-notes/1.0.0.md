## Português

**RansomGuard 1.0.0 — primeira versão pública.** Detecção e contenção de ransomware em servidores de arquivos
Windows, gratuita e de código aberto (MIT). Substitui a candidata `0.9.0-rc`, que não é compatível: os agentes dela
não se conectam a este painel.

**O que mudou desde a 0.9.0-rc**

- Sem licença nem pagamento: todos os recursos, inclusive a contenção, para todos.
- Cada agente tem a própria chave e assina os lotes; o enrolamento usa token de prazo e usos limitados. Não existe
  mais segredo compartilhado.
- Contenção conferida por efeito. A ordem é: bloquear o IP, negar a conta no compartilhamento, derrubar a sessão
  SMB e, por último, a cópia de sombra.
- Regravação em massa de arquivos existentes passa a ser Alta: o ataque que evita os canários é contido.
- O agente contém sozinho com o painel fora do ar e não fica preso tentando falar com ele.
- O painel virou serviço do Windows, com dados protegidos pela DPAPI da máquina e instalador completo.
- Canários com nomes e conteúdo próprios de cada instalação; arquivo de cliente com o mesmo nome nunca é tocado.
- Validado em laboratório, em rede real com Active Directory e Windows Server 2022 e 2025: veja
  [Proteção e limites](../pt-br/protecao-e-limites.md).

**Antes de usar**

- Comece em Monitor. Leia os limites: um ataque rápido sobre arquivos pequenos pode terminar antes da contenção, e
  Média nunca contém.
- Os instaladores **não têm assinatura de código**: o Windows avisa. Confira o SHA-256 e o atestado:
  `gh attestation verify <arquivo> --repo rodrigoimmaginario/ransomguard`.

## English

**RansomGuard 1.0.0 — first public release.** Ransomware detection and containment for Windows file servers, free
and open source (MIT). It replaces the `0.9.0-rc` candidate, which is not compatible: its agents do not connect to
this dashboard.

**What changed since 0.9.0-rc**

- No license or payment: every feature, containment included, for everyone.
- Each agent has its own key and signs its batches; enrollment uses a token with limited lifetime and uses. The
  shared secret is gone.
- Containment verified by effect. The order is: block the IP, deny the account on the share, drop the SMB session
  and, last, take the shadow copy.
- Mass overwrite of existing files is now High: the attack that avoids canaries is contained.
- The agent contains on its own with the dashboard down and does not get stuck trying to reach it.
- The dashboard is now a Windows service, with data protected by machine DPAPI and a complete installer.
- Canaries with names and content unique to each install; a customer file with the same name is never touched.
- Validated in a lab, on a real network with Active Directory and Windows Server 2022 and 2025: see
  [Protection and limits](../en/protection-and-limits.md).

**Before using it**

- Start in Monitor. Read the limits: a fast attack on small files can finish before containment, and Medium never
  contains.
- The installers are **not code-signed**: Windows warns. Check the SHA-256 and the attestation:
  `gh attestation verify <file> --repo rodrigoimmaginario/ransomguard`.

**Files**

| File | Purpose |
|---|---|
| `RansomGuard-Painel-1.0.0.msi` | Dashboard (central machine) |
| `RansomGuard-Agente-1.0.0.msi` | Agent (each file server) |
| `RansomGuard-Ensaio-1.0.0.exe` | Controlled attack drill (test workstation) |
| `*.sha256`, `SHA256SUMS.txt` | Hashes |
